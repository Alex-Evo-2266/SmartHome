## Объявления параметров

В `AutomationSchema.parameters` задаются `ScriptParameter` по ключу. Определение имеет discriminator `type`:

- `ValueParameter`: `type` — `number|string|boolean|time` (по умолчанию `string`), `default` — scalar или `null`.
- `PathParameter`: `type: "path"`, `default: string|null`.
- Обёртка `ScriptParameter`: обязательный `title`, необязательный `description`, `required` (по умолчанию `true`) и обязательный `definition`.

При инициализации `AutomationContext` значения default переносятся в runtime variables и проверяются по типу определения. В схеме `required` объявлен, но его наличие само по себе не означает наличие отдельного API-слоя для передачи формы параметров.

Пример:

```json
{
  "parameters": {
    "target": {
      "title": "Целевое поле",
      "required": true,
      "definition": {
        "type": "path",
        "default": "device.hall_light.state"
      }
    }
  }
}
```

## Разрешение `variable.<name>`

Пользовательские runtime значения доступны через path namespace `variable`, например `variable.target`. Разрешение выполняет `_resolve_variable` из `blocks/pathArg.py`; `resolve_path` вызывает её для этого namespace. Функция реализована, это не заглушка. Она требует `AutomationContext`:

1. `resolve_path` отделяет имя после `variable.`.
2. Контекст проверяет наличие переменной.
3. Отслеживание активных переменных не допускает циклической цепочки.
4. Если значение — строка, начинающаяся с известного корня (`device.`, `room.`, `system.` или `variable.`), она рекурсивно разрешается как путь.
5. Иначе возвращается сохранённое значение.

Таким образом, строка-путь в переменной может быть интерпретирована как ссылка на ресурс, а обычная строка — как данные. Сравнение с перечнем namespaces определяется реализацией `pathArg.py`.

## Использование в выражениях и шагах

Переменные не выделены в отдельный тип `ExpressionArg`; они адресуются `PathArg` с `path: "variable.<name>"` либо path-like `RefArg`. В `ActionStep` аргументы параметров проходят через общий resolver, кроме поля `path`, для которого runner может сохранять сам адрес ресурса. Это различие важно для команды `set_value`.

## Отсутствие значения и циклы

Ссылка на несуществующую переменную приводит к ошибке разрешения пути, а не к успешному `null`-результату. Циклические ссылки обнаруживаются через активный стек имён переменных в `AutomationContext`; ограничение глубины защищает рекурсивные вычисления. Подробные типы ошибок см. в [error-handling.md](./error-handling.md).

## Ограничения

- Не существует отдельного механизма объявления локальных переменных как шагов или присваивания переменной в графе шагов.
- `parameters` — метаданные/значения по умолчанию; документация не предполагает, что UI или API гарантированно предоставляет значения извне.
- Путь-строка в переменной разрешается только при совпадении с реализованным namespace-префиксом.
