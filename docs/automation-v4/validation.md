## Уровни валидации

### 1. Разбор Pydantic-моделей

HTTP-тело и YAML-документ разбираются через `AutomationSchema` и вложенные discriminated unions. Большинство моделей объявляет `extra="forbid"`; неожиданные поля отвергаются. Обязательность типов/полей и допустимые значения discriminator задаются непосредственно моделями.

Специальные проверки:

- `OnceTimeTrigger.run_at` парсится через `datetime.fromisoformat` и должен содержать часовой пояс.
- `WeeklyTimeTrigger.weekdays` должен содержать 1–7 элементов; каждый день — 0–6, затем список сортируется и очищается от дубликатов.
- `LiteralArg` выводит `data_type` из значения, если он не задан; `null` требует явного типа; заданный тип проверяется на совместимость.
- параметрические модели и команда запрещают лишние поля.

### 2. Ссылочная целостность `AutomationSchema`

`check_references` проверяет:

1. `entry` присутствует в ключах `steps`;
2. все заданные `next`, `on_true`, `on_false`, `on_timeout` указывают на существующие шаги;
3. `RefArg.ref` в выражениях, аргументах шагов и trigger conditions указывает на expression ID либо содержит точку и поэтому считается path-like;
4. обход аргументов выполняется для binary/unary/call/group выражений, action params, delay duration, condition value, await timeout и device/room trigger condition.

Проверка ссылки не гарантирует, что path реально разрешается в имеющемся состоянии устройства, комнаты или system namespace: это выясняется при runtime.

## Что не валидируется статически

- Значение команды `ActionStep.command` не сверяется с зарегистрированным реестром команд при создании `AutomationSchema`.
- Параметры команды не валидируются по метаданным команды на этапе корневой схемы.
- `IntervalTimeTrigger.interval` не ограничен положительным числом схемой.
- `MonthlyTimeTrigger.month_days` не имеет отдельного ограничения диапазона/длины в модели.
- Граф не проверяется на достижимость узлов, бесконечные циклы или наличие обеих веток условия.
- Проверка того, что каждое условие runtime даст ожидаемый тип, выполняется при вычислении, а не при загрузке.
- `ScriptActionStep` и interval trigger могут быть схемно валидны, но не поддерживаются runner/manager.

## Где выполняется

API проверяет тело до записи. `AutomationStorage` при загрузке также разбирает документ через модель, а strict/non-strict режимы `load_all` определяют поведение при ошибках отдельных YAML. Модельная ошибка API переводится в HTTP error; runtime ошибки возникают позднее в resolver/runner.

Проверка ссылок Markdown и примеров этой документации выполняется отдельно; см. итоговые результаты проверки в отчёте к изменению и файлы [examples.md](./examples.md).
