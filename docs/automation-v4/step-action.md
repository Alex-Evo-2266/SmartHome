## Структура

```json
{
  "type": "action",
  "command": "set_value",
  "params": {
    "path": {"type":"path","path":"device.hall_light.state"},
    "value": {"type":"literal","value":true,"data_type":"boolean"}
  },
  "next": "continue"
}
```

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `type` | literal `"action"` | да | Дискриминатор шага. |
| `command` | `string` | да | Имя зарегистрированной команды. |
| `params` | `dict[string, ExpressionArg]` | нет | Значения параметров команды; default `{}`. |
| `label` | `string \| null` | нет | UI-метка. |
| `next` | `string \| null` | нет | Следующий ID шага. |

## Исполнение

Runner разрешает каждый `params`-аргумент через `resolve_arg`. Исключение сделано для параметра с именем `path`, когда его модель — `PathArg`: вызывается `resolve_path(..., preserve_path=True)`, чтобы обработчику передавалась строка адреса, а не текущее значение поля. Затем runner передаёт `command` и итоговый словарь параметров внедрённому `action_handler(command, params)`.

Валидатор схемы знает типы аргументов и проверяет ссылки на expressions, но не проверяет наличие команды и её параметров против реестра на момент разбора `AutomationSchema`. Ошибка неизвестной команды возникает при диспетчеризации обработчика.

## Реестр команд

В `device_action_handler.py` есть реестр через `register_command`, introspection через `get_action_commands()` и async dispatcher с контрактом `async def device_action_handler(command: str, params: dict[str, Any]) -> None`. Dispatcher отклоняет пустое/нестроковое имя команды, `params` не-dict и неизвестную команду; иначе ожидает зарегистрированный handler. Путь действия передаётся внутри `params`, а не отдельным аргументом. Наблюдаемый встроенный обработчик — `set_value`.

Для `set_value` путь передаётся внутри `params["path"]`; поддержаны формы:

- `device.<system_name>.<field>` — установка значения конкретного поля;
- `device.<system_name>` — массовая установка устройства;
- `room.<room>.<device_type>.<field>` — установка поля для room/type;
- `room.<room>.<device_type>` — массовая установка для room/type.

Реализация проверяет наличие `path` и ненулевое значение, затем делегирует в операции установки состояния устройства/комнаты. Допустимые значения зависят от существующих устройств и полей; примеры выше показывают форму, а не гарантию наличия заданного ресурса.

## Ссылки и переменные в параметрах

Любой параметр, включая `value`, может быть `literal`, `ref` или `path`; общий resolver вычисляет его перед вызовом. Для `path`-параметра используйте `PathArg`, если команду нужно адресовать ресурсу. Если вместо него передать `RefArg`, специальная ветка сохранения пути не применяется. Путь, сохранённый в `variable.*`, может быть рекурсивно разрешён до значения; проверьте, нужно ли именно значение или адрес ресурса. См. [variables.md](./variables.md).

## Ошибки

Ошибка разрешения аргумента, неизвестная команда или отказ целевого setter приводят к ошибке шага; runner не возвращает success-shaped результат. Перечень уровней обработки — [error-handling.md](./error-handling.md).
